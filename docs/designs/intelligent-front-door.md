## Relationship to the plan of record

`2026-07-23-careos-boil-the-ocean.md` remains the ACTIVE program plan. This plan inserts one
wave program into it; it supersedes nothing and inherits every invariant (CLAUDE.md, docs/00
D-001..D-031). Source analysis: `docs/reviews/2026-08-12-takecareos-competitive-product-analysis.md`.

The competitive read in one line: TakeCareOS wins on legibility (one conversational door, one
alert queue, installable PWA); CareOS wins on everything enforceable (forced RLS, AAL2,
append-only, verifiable audit chain, DB-enforced AI tiers). This program closes the legibility
gap using rails that already exist, and makes each taken feature *provably* smarter: theirs
drafts, ours drafts inside enforced tiers with deterministic pre-flight evidence.

## Vision

### 10x Check
The agency runs through one door. A coordinator types or says what they need; the platform
answers from RLS-scoped retrieval or drafts the action as a tiered proposal with a
deterministic pre-flight report attached. A caregiver ends a shift, talks for thirty seconds,
and the note comes back coached against the client's actual care-plan goals before it is
saved. Every item needing attention is in one ranked, acknowledgeable queue. And when a
surveyor or buyer asks "prove it," one screen renders the policy matrix, the audit-chain
verification, and the AI kill-switch table live. Nobody in the market can render that screen.

off never takes down the door.

## Error & Rescue Registry (new codepaths)

| Codepath | Failure | Rescued? | Action | User sees |
|---|---|---|---|---|
| command intent parse | LLM malformed/empty JSON | Y | 1 retry, then degrade | "I couldn't work that out — try rephrasing" + module links |
| command intent parse | model refusal | Y | no retry | same degrade copy; logged w/ prompt_version |
| capability resolution | kill switch off / budget exceeded | Y | fail closed | "This assistant feature is switched off" (CAREOS_AI_DISABLED / _BUDGET) |
| draft→approval | capability disabled in between | Y | fail closed: recorded as `rejected` w/ reason `capability_disabled` (existing 0016 vocabulary — no new event type) | "This draft can no longer be approved — feature was disabled" |
| proposal approve | Lane-B RPC raises (CAREOS_*) | Y | surface mapped copy | the RPC's plain-language error; draft stays pending |
| preflight assembly | any check RPC errors | Y | block draft, never guess | "Couldn't verify credentials/schedule — not drafting until checks run" |
| note coach | LLM error/timeout | Y | silent degrade, note saves | note saves normally; coach panel shows "suggestions unavailable" |
| voice capture | offline / >size cap / bad type | Y | disable or reject loudly | offline copy per R2; "recording too long" with cap stated |
| STT (gpt-transcribe) | vendor error/timeout | Y | keep audio, retry once, then manual | "Transcription failed — audio saved, try again or type" |
| PDF import | encrypted/scanned/huge | Y | reject to honest path per R3 | scan copy; "file too large (max N MB)" |
| PDF field detect | low confidence | Y | draft flags fields <threshold | per-field "check this" markers |
| attention queue | source query degraded | Y | per-source fallback row | "Credential alerts temporarily unavailable" section state |
| web push | permission denied / sub expired | Y | in-app queue is always primary | queue unaffected; settings shows push state honestly |
| family draft | consent absent/expired | Y | deterministic pre-check, never drafts | "No active consent — draft not generated" |

Failure Modes Registry: every row Rescued=Y, Logged=Y (`ai_interaction` / `audit_event` /
structured logs), Tested=AC. **Zero CRITICAL GAPS** (no silent failures by design).
